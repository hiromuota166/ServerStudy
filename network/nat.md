# NAT

## ひとことで言うと
内側の機器が外に出るときに、**送り主の住所（IP）を書き換えて、その記録をメモ帳に残しておく** 仕組み。返事はメモ帳を見て、元の機器に戻す。

## 仕組み
覚えるのは3つだけ。

1. **書き換える**：送り主を、自分の住所に書き換えて外に出す
2. **メモ帳に記録する**：「さっきの通信は、中の誰のものか」を覚えておく（変換表）
3. **返事を戻す**：返ってきた返事を、メモ帳を見て元の機器に渡す

```
Ubuntu（192.168.100.10）            📦 送り主：192.168.100.10
  ↓
Windows（NAT その1）  書き換え + メモ   📦 送り主：192.168.11.10
  ↓
自宅のルーター（NAT その2）書き換え + メモ 📦 送り主：グローバル IP
  ↓
ubuntu.com（グローバル IP しか見えない）
```

### 会社の電話にたとえると
| 会社の電話 | NAT |
|---|---|
| 社内の内線番号（社外からはかけられない） | プライベート IP（`192.168.x.x`） |
| 外にかけると、相手には会社の代表番号が表示される | 送り主を書き換える |
| 折り返しが来たら、交換台が「さっき外にかけたのは誰か」を覚えていて、その人につなぐ | メモ帳（変換表）を見て戻す |
| 知らない人が代表番号に突然かけてくると、誰につなげばいいか分からない | 外からは入れない |
| 「8080 番宛ては Ubuntu さんにつないで」と交換台に頼んでおく | ポートフォワーディング |

### なぜこんな面倒なことをするのか
IPv4 の住所（グローバル IP）は世界で約43億個しかなく、足りない。家の中ではプライベート IP を自由に使い、外に出るときだけ1つのグローバル IP を共有する。家の iPhone も Windows も、外から見ると同じ住所。

### 外から入れない理由
外から突然来た通信は、メモ帳に記録がないので、誰に渡せばいいか分からず捨てられる。これがセキュリティ上の壁にもなっている（ただし、ファイアウォールの代わりにはならない）。

## 自分の環境では
NAT が **2段（二重 NAT）** になっている。

| NAT | 書き換え前 | 書き換え後 |
|---|---|---|
| Windows（`New-NetNat` で作った NATNetwork） | `192.168.100.10` | `192.168.11.10` |
| 自宅のルーター | `192.168.11.10` | グローバル IP |

- **iPhone から Ubuntu が見えなかった** → Windows の NAT のメモ帳に記録がないから
- **ポートフォワーディングで見えた** → メモ帳に「8080 番は Ubuntu の 80 番へ」と手で書いたから
- **Tailscale はポートフォワーディングなしで届いた** → Ubuntu のほうから外に接続しにいくので、メモ帳に記録が残り、そこを通って返事（トンネル）が入ってこられるから（→ [VPN と Tailscale](../security/vpn.md)）
- **Windows → Ubuntu の ssh は書き換えなし** → PC の中だけで完結する通信なので NAT は関係ない。ログイン時の `Last login ... from 192.168.100.1` がその証拠
- ルーティング表は `Find-NetRoute -RemoteIPAddress 192.168.100.10`（Windows）で確認できる。`192.168.100.x` 宛ては NATSwitch から直接、それ以外は Wi-Fi からルーター（`192.168.11.1`）へ出ていく
