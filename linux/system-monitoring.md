# サーバーの健康状態を見る

## ひとことで言うと
CPU・メモリ・ディスク・起動時間を、`top` / `free` / `df` / `uptime` で見る。数字は Linux が `/proc` に置いている。**CPU 使用率は「どれだけ忙しいか」、ロードアベレージは「どれだけ行列ができているか」**。

## 見るコマンド

| コマンド | 見えるもの |
|---|---|
| `nproc` | CPU のコア数（同時にできる仕事の数）。今は `3` |
| `uptime` | 起動してからの時間と、ロードアベレージ（1分・5分・15分） |
| `free -h` | メモリ |
| `df -h /` | ディスク |
| `cat /proc/loadavg` | `uptime` が読んでいる元のファイル。`0.22 0.13 0.10 1/189 37834` の `1/189` は「今動いている数 / 全部の数」 |
| `top` | 全体の様子 + CPU を使っている順のプログラム一覧（`q` で終了） |

## /proc
Linux が **自分の今の状態をファイルとして見せてくれる場所**。ディスクに保存されているわけではなく、読むたびに OS がその場で中身を作る。`top` も `uptime` も、自作 API が使っている `psutil` も、ここを読んでいる。

## CPU

- `top` の `%Cpu(s): ... 99.4 id` の `id`（idle）は **暇な割合**。**CPU 使用率 ＝ 100 − id**
- 使用率は **全コアの平均**。3コアのうち1コアが全力なら 33%

## ロードアベレージ

「CPU を使いたくて動いている・待っているプログラムの数」の平均。**コア数と比べて読む**。

| ロード（3コア） | 意味 |
|---|---|
| 0.12 | ほぼ暇 |
| 3.0 | ちょうど満席 |
| 6.0 | 3人が席の空きを待って行列になっている |

3つの数字の差で流れが読める。

| 形 | 読み方 |
|---|---|
| 1分 ≫ 15分 | 忙しくなり始めたばかり |
| 3つとも高い | ずっと忙しい（要注意） |
| 1分 ≪ 15分 | 落ち着いてきた |

## メモリ：見るのは available

```
total 3.3Gi = used 637Mi + free 1.2Gi + buff/cache 1.8Gi
                                          ↓ 必要になったら返せる
available 2.7Gi ≒ free + 返せる buff/cache
```

| 項目 | 意味 |
|---|---|
| used | プログラムが使っている |
| free | 何にも使っていない |
| buff/cache | 空いているメモリを、ファイルの読み込みを速くするために借りている分。必要になったらすぐ返す |
| available | 新しいプログラムが **実際に使える量**。足りているかはここを見る |

- 「free が少ない＝メモリ不足」は勘違い。Linux は空きメモリをキャッシュに使っておく
- 再起動直後は buff/cache が空になる（実際に 1795 → 440 MiB に減った）。動かしているとまた増える
- Swap の used が `0B` ならメモリは足りている

### iOS との比較

| Linux | iOS |
|---|---|
| buff/cache を返す（誰も損しない） | `NSCache` や purgeable メモリが捨てられる |
| Swap に逃がす | なし（iOS はメモリ圧縮） |
| **OOM killer**（プロセスを強制終了） | **Jetsam** |

## PID（プロセス ID）
動いているプログラム1つ1つに OS が付ける整理番号。起動するたびに新しい番号になる。

- **PID 1 は `systemd`**。最初に動くプログラムで、全部の親
- 再起動後の cloudflared は PID が小さい（1145）＝ 起動してすぐ systemd が立ち上げた
- `/proc/PID番号/` でそのプログラムの情報が見られる。止めるのは `kill PID番号`
- Xcode のデバッグナビゲーターに出る番号と同じもの

## 再起動が必要か

```
cat /var/run/reboot-required
```

`*** System restart required ***` と出たら、カーネルなどが更新済みで、再起動するまで古いまま動いている。再起動するのは Ubuntu（VM）だけで、Windows は関係ない。再起動の間は公開サイトも止まる。

## 再起動しても自動で動く約束：systemd の enabled

```
systemctl is-enabled cloudflared nginx ssh tailscaled
```

- `enabled` のサービスは起動時に自動で立ち上がる。cloudflared は `service install` のときに登録された
- ssh だけ `disabled` なのは **ソケット起動** のため。`ssh.socket`（22番で電話番だけする）が `enabled` で、接続が来たら `ssh.service`（本体）を起こす。使うまで作らない lazy な初期化と似ている

## 負荷をかけて見る（stress-ng）

```
sudo apt install -y stress-ng
stress-ng --cpu 3 --timeout 90s
```

| 実験 | CPU 使用率 | ロード |
|---|---|---|
| `--cpu 1` | 33% | 約1 |
| `--cpu 3` | 100% | 約3（ちょうど満席） |
| `--cpu 6` | 100%（頭打ち） | 約6（行列） |

- 同じ 100% でも、ロードを見れば「満席」か「行列」かが分かる。だから両方見る
- CPU が 100% でも、API の応答時間はほとんど変わらなかった（0.58秒。うち 0.5秒は `cpu_percent(interval=0.5)` で自分が待っている分）
- 遅くならないのは **スケジューラー**（カーネルの中の CPU の配り係）が、動きたいプログラムに数ミリ秒ずつ順番に CPU を使わせるから。nginx は関係ない
- 優先度は `top` の `NI`（nice 値）。iOS の QoS に近い
